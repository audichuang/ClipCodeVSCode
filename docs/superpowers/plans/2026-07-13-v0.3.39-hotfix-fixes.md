  bug is real.** If you cannot make it fail, the finding is a false positive —
  mark it `NOT-REPRODUCED` in your final report and do NOT change code for it.

  caller) and make the test pass. Keep the existing tests green.
- Comments in English. Do not reformat unrelated code. No line-ending changes.
- Preserve `--cached` / `--cached --reverse` direction (review confirmed it is
  currently correct — do not "fix" it).
- **Do NOT stash, drop, or delete untracked files (especially this plan doc).**
  Leave any untracked files in the worktree exactly as they are.
- Work in priority order B → C → D. Commit per batch with a clear message.
- Report each item as REPRODUCED+FIXED / NOT-REPRODUCED / PARTIAL with its

## Batch B — P1: mutation routing / wrong-state (high value)

### B1. Rename stage/unstage drops the old path
- `graph/src/git/git-service.ts:902`, `graph/src/git/git-service.ts:2189`
- Status parsing records `oldPath` but `getUncommittedDiff()` drops it; only `new`
  reaches git → staging leaves `old` as unstaged deletion; unstaging leaves `old`
  staged for deletion. Fix: thread `oldPath` through stage/unstage of a rename so
  both sides move together. Test: rename old→new, stage the node, assert index
  shows the rename (not new-only + old-deletion).

### B2. Cross-repo / wrong-side multi-select not filtered by group
- `graph/src/tree/changes-workbench.ts:168`, `graph/src/tree/changes-workbench.ts:366`
- Stage/Unstage handlers trust every selected item without filtering by `group`
  (repo + staged/unstaged side). Ctrl-select B's Staged node + A's Unstaged file,
  invoke Stage on A → B's worktree edits get staged too. Fix: filter selection to
  the invoked repo + side before mutating. Test: mixed-repo/mixed-side selection,
  assert only the invoked group is mutated.

### B3. Stale numeric hunk/line index without diff fingerprint
- `graph/src/git/git-service.ts:2321`, `graph/webview-ui/src/diff/messaging.ts:89`,
  `graph/src/panels/DiffPanel.ts:155`
- Selections carry only numeric indices; service refetches diff without validating
  a fingerprint → if file/index changed between render and click, the index maps to
  a different hunk and stages the wrong content. Fix: attach a diff generation/hash
  to the rendered diff; on mutate, re-fetch and reject (or re-map) if the fingerprint
  no longer matches. Test: render, mutate the file underneath, click old index,
  assert the stale mutation is rejected rather than applied to new content.

### B4. `commitSelected` omits `assertHunkStageable` guard
- `graph/src/git/git-service.ts:2435`
- `stageHunks` guards mode-only/unstageable hunks; `commitSelected` doesn't → mode
  change 0644→0755 + two content hunks, commit only hunk 0 → the chmod is committed.
  Fix: apply the same guard in `commitSelected`. Test: mode change + content hunks,
  commit one content hunk, assert chmod not included.

### B5. Raw-diff helpers swallow git failures as empty diff
- `graph/src/git/git-service.ts:2298`, `graph/src/git/git-service.ts:2312`,
  `graph/src/panels/DiffPanel.ts:59`
- Timeout / corrupt index / spawn failure / failed `--no-index` all become "no
  changes" (or a false whole-file add/delete in the content provider), hiding the
  real failure. Fix: distinguish genuine empty from error; propagate an error the
  UI shows as a banner (the workbench already has this pattern). Test: force a git
  failure, assert error surfaced (not empty/no-changes).

### B6. Busy gate has no operation id → cross-panel unlock
- `graph/webview-ui/src/diff/messaging.ts:35`, `graph/src/panels/DiffPanel.ts:175`
- Single `busy` gate cleared by any reply. Stage A → navigate to B & stage → A's
  late error unlocks B; next click can hit a shifted hunk. Fix: correlate replies to
  request/op ids; only the matching op clears its gate. Test: interleave two ops,
  assert a stale reply does not unlock the newer op.

### B7. Image diff lifecycle omits repo + generation
- `graph/webview-ui/src/diff/Diff.svelte:57`,
  `graph/webview-ui/src/components/common/ImageDiff.svelte:29`,
  `graph/src/panels/DiffPanel.ts:241`
- Repo A `img.png` → repo B same-named file keeps the side-keyed component without
  refetch; a late A response matches B by `path+ref` → B shows A's image. Fix:
  include repo id + generation in the image component key / response correlation.
  Test: switch repos with same-named image, assert B fetches and shows B's image.

## Batch C — P1: blame & diff-UI lifecycle / correctness / perf

- C1 `:142` stale request overwrites newer (doc version compare ineffective — same

- C2 `:131` timeout/failure catch clears ALL decorations before freshness check →
  blank-but-enabled. Only clear if this request is still current.
- C3 `:61` close tab + reopen same URI/column inherits enabled + stale cache/gen.
  Reset per-editor state on close.
- C4 `src/blame/index.ts:13` no rerender on commit/checkout/rebase when text
  unchanged → stale SHAs / "你 · 未提交". Subscribe to git repo/HEAD change events.

  stale. Rerender all visible editors of the document.

  20k after enable). Re-check the cap on each render.
- C7 `:90` debounce >300ms starts another uncancelled process each time. Cancel the
  in-flight child process before starting a new one.
- Each: one controller test (cross-file cache, render race, close/reopen, HEAD
  change, split pane) — the review notes none exist today.
