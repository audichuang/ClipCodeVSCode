# Snipcode（VS Code）UI 全面審查 — 2026-09-06

> 目標：找出「顯示不夠清楚、一目了然」的地方，做到比 IntelliJ 的 Git 工具更好用。
> 只審不改。附錄（六份分面向詳細報告 + 截圖）在 `2026-09-06-ui-audit/`。
> 版本：v0.3.42（`d657fca`），工作樹乾淨。

## 0. 範圍與方法

**審了什麼**：commit graph 線圖、graph webview 主面板（Toolbar / 欄位 / 詳情面板 / 搜尋 / 右鍵 / 鍵盤 / modal）、Snipcode Diff tab 與 commit-details 內的 diff、PR compare tab、側邊欄（Snipcode Git 容器 + SCM 六個 view + package.json contributes）、i18n。

**證據等級**（每條 finding 都標）：
- `[截圖]`：用 `verify-webview-ui` 那套 harness，在合成 repo（42 commits、6 分支、3 merge、remote 領先/本地未推、tag/stash、髒工作樹）上以**真 parser** 產 fixture、headless Chrome 渲染。dark / light / 2x / 900px 窄 / 詳情面板 / Diff tab / commit box 共 8 張。
- `[dist]`：對打包後的 `dist/graph-webview/*.css`、`.vsix` 內容實際計數。
- `[程式碼]`：從原始碼推導，未渲染。

**沒審或只掃過**（使用者說「完整看」，這裡誠實列出缺口）：inline blame（`src/blame/`）、Stats / Reflog 分頁只掃版面、Interactive rebase 只看進入方式、45 個 modal 只抽樣 8 個、Snipcode History view 只有一條 P2、Workbench commit box 只有 320px 一張截圖。**側邊欄 TreeView 與 PR tab 沒有截圖**（TreeView 是原生元件，harness 拍不到；PR tab 需要另一輪 fixture）。harness 內嵌 60 個 `--vscode-*` 變數，但不會重現真 webview 的 `body { padding: 0 20px }`。

**對照基準**：JetBrains 官方 Help（Log tab / Commit tool window / Diff viewer / Compare branches / GitHub PR）逐字核對，見附錄 `jetbrains-baseline.md`。文件沒寫的一律標「未確認」，不憑記憶。

## 1. 既有優勢（修的時候別拆掉）

- Diff tab **同檔 staged + unstaged 同畫面** + hunk / line / block 級 stage（IntelliJ 與 VS Code 原生都沒有）。
- 預設 `--topo-order`（IntelliJ 預設 date order）。
- 獨立 Reflog 分頁（IntelliJ 沒有 UI）。
- Image diff 有 side-by-side / swipe / onion skin。
- 多 repo Fetch / Pull / Push All 含逐 repo 進度與 ↓↑ badge。
- lane 顏色 ↔ badge 色條對應（IntelliJ 的右置 label 沒有這層）。
- PR tab 三點語意（merge-base）正確、rename 用 `-M` 偵測、requestId 競態防護、測試 1070 行。
- 鍵盤 Ctrl/Cmd+↑↓ 跳 parent / child 且帶路徑記憶（`graph-navigation.ts`）。

## 2. 跨面向主題（一個修法打多個表面）

**X1 語言三重斷裂** `[程式碼][dist]`
- 繁中使用者拿到**簡體**：`webview-ui/src/lib/i18n/index.svelte.ts:20-23` 把 `zh-TW` 截成 `zh` → 簡體字典（统计 / 筛选 / 储藏 / 遴选 / 变基）。
- Host 端 l10n **沒進 VSIX**：root `package.json` 無 `"l10n"` 欄位（只有 `graph/package.json:35` 有），`.vscodeignore:25` 排除 `graph/l10n/**`，`unzip -l *.vsix | grep l10n` = 0。`MainPanel.ts:824,850` 與 `status-bar.ts:14` 用 key 風格 `vscode.l10n.t('checkedOut', …)` → 使用者看到原始 key。
- 硬編字串散落：側邊欄繁中硬編（`Workbench.svelte:17,22,35`、`changes-workbench.ts:163,285…`）、PR/主面板/Diff 英文硬編（`Filter branches…`、`Loading...`、`No staged changes`、`Copy Full Source`、Modal 的 `Close (Esc)`）。無 `package.nls.json`，view 名 / 命令名不可在地化。
- 修法：新增 `zh-tw.ts` 字典 + `setLocale` 先查完整 locale；root `package.json` 加 `"l10n": "./graph/l10n"` + `.vscodeignore` 放行 + `bundle.l10n.zh-tw.json`；硬編字串走 `t()` / `vscode.l10n.t`；加 `package.nls.json`。

**X2 全產品沒有任何 +/− 統計** `[截圖][程式碼]`

**X3 Rename 呈現壞掉** `[程式碼]`
- 單檔 diff 變「整檔新增」：`git-service.ts:1607-1640` `commitFileDiff` 與 `:1007` `getUncommittedFileDiff` 的 pathspec 只帶新路徑，git 配不到 rename。修法：呼叫端帶 `oldPath` → `-M -- <old> <new>`。
- rename-only / mode-only 變更 hunks 為空 → `FileDiffView.svelte:567-628` 渲染**一片空白無字**。
- 列表只有字母 R：PR `PrView.svelte:694`、側邊欄 `changes-tree.ts:92-100`（`oldPath` 在 wire 上但未渲染）、詳情 `CommitDetails.svelte:995`。
- 順帶行為問題：staged rename 走 hunk unstage 時 raw 無 `rename from` header，`assertHunkStageable`（`git-service.ts:71-75`）擋不到 → `apply --cached --reverse` 一個 `new file` patch 把 index 裡新路徑整個拿掉。

**X4 Uncommitted 的三重斷裂**
- 線圖節點**懸空**：`MainPanel.ts:149` 與 `git-service.ts:834` 都是 `parents: []` → SourceGit 演算法把它當 root，dot 落在 lane 0、沒有線。截圖 `graph-dark.png`：虛線圈正上方是藍色 feature lane，HEAD develop 在 lane 1，看起來像 uncommitted 屬於別的分支 `[截圖]`。
